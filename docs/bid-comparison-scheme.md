# 标书对比详细方案（原本·标书查重）

> 基线版本：v0.5.0 · 更新日期：2026-07-05
>
> 第 1–7 节描述已实装并可运行的能力（标注对应源码位置），第 8 节是已知短板，第 9 节是 v2 改进路线，第 10 节是验收指标。
> 相关文档：[architecture-analysis-v0.4.md](architecture-analysis-v0.4.md)（架构深度分析）、
> [multi_document_compare_react_tauri_arch_design.md](multi_document_compare_react_tauri_arch_design.md)（系统设计蓝图）、
> [bid-comparison-sota-survey.md](bid-comparison-sota-survey.md)（SOTA 全景调研，不受实现约束的上限参考）。
> 本文聚焦"对比方法论"的汇总。

## 1. 目标与范围

**核心场景**：对同一招标项目下的 2–5 份投标文件做交叉比对（不是单文档自查重），找出雷同条款、深度洗稿、事实矛盾，并给出围标串标嫌疑分级。全程离线运行，结果可举证、可人工复核、可导出。

**输入**：docx / pdf（含扫描件）/ txt / md / xlsx，每份标书一个文档。

**输出**：相似度矩阵、条款聚类（8 类差异分类）、逐对高亮 diff、事实冲突清单、围标嫌疑等级（含信号分解）、六格式导出报告（HTML/JSON/CSV/Markdown/XLSX/DOCX）。

**明确不做**：大模型自动法律审查、云端协作。

## 2. 总体流程：两期八阶段

```
导入期（每份文档独立，一次备料多次比对）
  ① 解析 → ② 标准化 → ③ 分块 → ④ 特征提取 → ⑤ 向量化（可选）

比对期（跨文档）
  ⑥ 候选召回 → ⑦ 精排评分 → ⑧ 聚类 → 差异分类/diff → 事实冲突 → 矩阵/围标 → 报告
```

导入期结果落库（SQLite，14 表），embedding 按 `(normalized_hash, model_id)` 内容寻址缓存，换比对参数不用重新解析。编排入口在 `src-tauri/src/services/compare_service.rs` 的 `run_compare()`。

## 3. 导入期：解析与备料

### 3.1 文档解析（`src-tauri/src/engine/parse.rs`）

| 格式 | 方案 |
|------|------|
| DOCX | zip + quick-xml，识别表格、标题层级（含 WPS 中文样式 id） |
| PDF | 三级回落：pdfium → pdf-extract（纯 Rust）→ OCR（PaddleOCR ONNX） |
| TXT/MD | UTF-8 / GBK 自动识别 |
| XLSX | calamine，每行原子化为一个块，单元格以 ` \| ` 连接 |

关键处理：

- **页眉页脚剔除**：同一文本在 ≥60% 页面重复且出现 ≥3 页即判定；
- **OCR 版面保留**：返回每页 `{t,x,y,w,h}` 坐标 JSON，供原文预览叠加可选中文本层；
- **截断提示**：扫描件超 20 页会截断但显式提示（`truncation_notice`），不静默丢内容。

### 3.2 文本标准化（`src-tauri/src/engine/normalize.rs`）

规则链按序执行：

1. Unicode NFKC 全角转半角；
2. 中文数字 + 单位转阿拉伯形式（"五万元"→"50000元"，年份"二〇二六年"逐位转换）；
3. 连续空白压缩、换行归一化；
4. 标点/大小写规范（可配置）。

数字内小数点和千分位逗号保留，避免金额被破坏。这一步是让"洗稿改写"在词面层现形的基础。整条规则链按确定性设计，同输入跨版本输出一致。

### 3.3 分块（`src-tauri/src/engine/chunker.rs`）

三档粒度同表共存：

- **section**：≤6000 字（无标题时），带标题路径；
- **paragraph**：自然段落；
- **sentence**：jieba + 中英文标点边界。

两条领域特化规则：

- **表格行原子化**（`is_table_row`）：表格行不拆句，diff 走列对齐——表格的证据价值在金额/数量而非表头模板文字；
- **模板标记**（`is_template`）：与常见招标文件模板余弦 ≥0.7 的块打标，比对时可剔除但保留在库中可解释——避免"响应招标文件格式要求"这类必然雷同的内容制造误报。

### 3.4 特征提取（`src-tauri/src/engine/features.rs`）

每块同时生成：

- `exact_hash` / `normalized_hash`（SHA256）；
- jieba 分词 tokens；
- 字符 3-gram MinHash（128 个哈希，splitmix64 派生仿射变换，确定性、无外部依赖）；
- 实体：金额 / 日期 / 工期 / 比例 / 主体；
- TF-IDF 稀疏向量；
- 章节路径（`section_path`）、表格行/列表项标记。

### 3.5 语义向量化（可选，`src-tauri/src/engine/embed.rs`）

模型可选 bge-large-zh / multilingual-e5 系列，ONNX Runtime 本地推理，支持内置和按需下载。语义层专门用于抓"换句式洗稿"——词面全变但意思不变的段落。向量按 `(normalized_hash, model_id)` 缓存，重复比对不重算。

## 4. 比对期：召回与评分

### 4.1 五通道候选召回（`src-tauri/src/engine/candidate.rs`）

直接两两全比是 O(M²)，用五通道倒排召回压到 O(M·k)：

| 通道 | 条件 | 抓什么 |
|------|------|--------|
| exact_hash 桶 | 哈希相同 | 原样照抄 |
| normalized_hash 桶 | 标准化后相同 | 改格式不改字 |
| 3-gram MinHash 倒排 | 共享 ≥3 个 gram；df ≥ max(256, N/10) 的高频 gram 停用 | 局部改写 |
| TF-IDF TopK | 点积 ≥0.25，每块 top 100 | 主题相似 |
| Embedding TopK | 余弦 ≥0.78，每块仅取 5 个（宁缺毋滥） | 深度洗稿 |

只召回跨文档候选，同文档内块不互比。

### 4.2 精排评分（`src-tauri/src/engine/scoring.rs`）

五维加权（启用语义时为六维）：

| 维度 | 权重（无语义） | 说明 |
|------|------|------|
| 词面相似 | 0.40 | token 余弦/Jaccard |
| 字符 n-gram | 0.30 | Jaccard |
| 实体相似 | 0.15 | 金额/日期等集合重合度；**表格行实体权重 ×2** |
| 结构相似 | 0.10 | 章节路径 Dice，剥掉文档标题根（标书 H1 必然不同） |
| 顺序相似 | 0.05 | 相对位置差 |

启用语义后 embedding 占 0.35，其余按比例压缩。

两个防误报设计：

- **不可测维度踢出分母重分配**（而非记 0 或 1）：双空记 1.0 会给无关短文本凭空加满分权重；
- **短文本动态阈值**：<30 字阈值上浮 +0.08 封顶 0.98——"按合同执行。"这类短句词面重合天然高。

### 4.3 聚类（`src-tauri/src/engine/clustering.rs`）

边分 ≥0.7 进并查集生成连通分量；成员 ≥4 且边密度 <0.55 的分量做**低内聚迭代拆分**（删最弱边递归），解决 A≈B≈C 但 A≉C 的"过桥"误聚。每文档在簇内选一个 primary（与其他文档平均相似度最高者），其余为 duplicate_candidate。

### 4.4 八类差异分类 + 分级 diff（`src-tauri/src/engine/diff.rs`）

| 分类 | 判定 |
|------|------|
| same | 分数 ≥0.95 |
| minor_change | 0.85–0.95，无关键实体变化 |
| rewrite（洗稿） | 0.70–0.85 且语义 ≥0.80、词面 <0.50 |
| changed | 0.70–0.85 |
| uncertain | 0.55–0.70，不硬判，转人工复核 |
| added / deleted | 单边存在（deleted 低于 0.55 下限时降为 uncertain） |
| conflict | 事实冲突改判，优先级最高 |

diff 按长度分级：≤60 字字符级，≤400 字词级，长段落句级再细化，表格行按列对齐逐格比。

## 5. 事实冲突检测（`src-tauri/src/engine/fact.rs`）

抽取金额（含大写、千分位、¥ 前缀）、日期、工期、比例、主体，主体做**阵营归一**（招标人/甲方→owner，投标人/乙方→supplier）。三条防误报规则：

- **集合互不包含才算冲突**：A 列了三笔付款、B 只提首笔，是信息缺失不是矛盾；
- **跨阵营互换才触发**（甲方付款变成乙方付款）；同阵营表述差异（"我司" vs "我公司"）不触发；
- **日期粒度兼容**："2026 年 6 月"与"2026 年 6 月 10 日"不判冲突。

## 6. 围标综合判定（`src-tauri/src/engine/collusion.rs`）

五信号线性叠加：

| 信号 | 权重 | 触发条件 |
|------|------|----------|
| ① 文本相似峰值 | 0.40 | 矩阵峰值 ≥0.6 起线性计分 |
| ② 跨文档雷同条款 | 0.10–0.40 | ≥3 份文档共现同一条款 |
| ③ 元数据同源 | 0.25 | ≥2 份的作者/最后修改人/制作软件一致 |
| ④ 共有罕见特征词 | 0.10 | ≥5 个罕见词共用（IDF 过滤常用词） |
| ⑤ 报价梯度 | 0.15 | 报价差 <3% 且 ≥3 条雷同条款（锚定"投标价"，排除注册资本干扰） |

分级：≥0.6 **high**（立即人工复核）；0.35–0.6 **medium**（重点复核）；0.1–0.35 **low**（建议抽查）；<0.1 none。

相似度矩阵用覆盖率定义（`src-tauri/src/engine/matrix.rs`）：

```
sim(A, B) = Σ(边分 × 较短块字数) / min(A 总字数, B 总字数)
```

## 7. 结果呈现与人工复核

- **矩阵页**（`src/screens/Matrix.tsx`）：交叉热力矩阵 + 文档元数据指纹 + 围标结论及信号分解；
- **聚类列表 → 条款详情**（`src/screens/ClusterDetail.tsx`）：多文档并排（十天干匿名列头）、diff 高亮、事实冲突表、批注；
- **人工复核三态**：待定 / 确认 / 排除——机器只给证据和分级，结论权留给评标人；
- **导出**（`src-tauri/src/export/`）：六格式，可附配置快照与原文，保证报告可复现可举证。

## 8. 已知短板（v1 基线，按优先级）

1. **判定可信度（最高优先）**：围标五信号权重和三条分级线目前只基于评标经验，**没有带标注案例的回测校准**（解法见 §9.3）。
2. **对抗鲁棒性**：扫描件 20 页截断（对手可把雷同内容放后面）、CSP 为 null、离线闸门有缝隙（`model_cached()` 判定过宽）、模型下载无 sha256 校验。
3. **性能天花板**：embedding 召回是 O(N²) 暴力余弦，大语料需换 ANN 索引；句级 diff 最坏 O(E²)。
4. **工程收尾**：报价梯度的"投标价"锚定仍不完整（业绩合同额可能劫持）、前端组件测试覆盖低、CI 只编译 macOS。

## 9. v2 改进路线

整体骨架（多通道召回 → 精排 → 聚类 → 人工复核）不推翻——这是查重领域的标准架构，换成纯 LLM 方案会丢掉"可举证、可复现、离线"三个立身之本。改进集中在三个层面：证据强度、比对方法论、校准方法。

### 9.1 证据层升级：从"文本像"到"同一来源"（性价比最高）

v1 围标信号里最硬的证据只有"元数据同源"（作者/软件一致），但易伪造也易漏。补四类取证级信号，成本低、证明力强：

1. **OOXML rsid 指纹**：Word 每次编辑会话给段落打 `w:rsidR` 修订标识，两份 docx 共享大量相同 rsid ≈ 铁证来自同一母文件，改作者名、换公司抬头洗不掉。解析层已在用 quick-xml 拆 docx（`engine/parse.rs`），顺手提取 rsid 集合算重合度即可，实现成本约一天。
2. **共同错误指纹**：查重取证的金标准——共享同样的错别字、标点错误、多余空格，比共享正确内容的证明力强一个量级。在现有"共有罕见特征词"（`engine/collusion.rs`）基础上，把"罕见"收窄到"疑似错误"（词典外词、异常标点模式）。
3. **分项报价向量相关性**：比"总价差 <3%"强得多的真实评标信号——各家分项报价表提成单价向量，两两算相关系数，>0.95 说明同一张成本表乘了系数。XLSX 表格行已原子化，数据基础现成。同时抓"相同的算术错误"（合计错得一样 = 同一张源表）。
4. **内嵌图片感知哈希**：资质扫描件、施工图在多份标书里出现同一张图（像素级或 pHash 级相同）。

### 9.2 方法论升级：两处结构性改进

1. **段落对齐（passage alignment）替代散点 chunk 配对**：v1 产出几百个独立块级配对，评标人看到的是碎片。改为 PAN 查重评测标准的 **seed–extend–filter**：以现有召回命中为种子，沿文档顺序把相邻种子扩展合并成连续对齐区段，再过滤短噪声。产出从"137 个雷同块"变成"乙文档第 3 章与丙文档第 3 章整体雷同（覆盖 82%）"，证据贴近人的心智模型。v1 的顺序维度（order sim）已暗示此方向，只是没走完。
2. **交叉编码器复核 uncertain 带**：0.55–0.70 区间 v1 直接转人工，量大时是复核瓶颈。加小型 cross-encoder（如 bge-reranker，ONNX 本地推理，与现有 embedding 基建同栈）只对这个窄带重打分，自动分流"其实是洗稿"和"其实无关"，人工只看真正的边界案例。对洗稿的判别力远高于双编码器余弦，且只跑窄带、性能可控。

### 9.3 校准方法升级：合成对抗语料生成器

真实围标案例难拿，不必等。拿正常标书程序化施加变换（同义替换、句序打乱、数字微调、格式转换、OCR 噪声、"母文件分发多家改抬头"模拟），自动获得带标注正负样本。有了它：

- 五维评分权重和围标信号权重从经验值改为逻辑回归拟合；
- 分数做等渗校准（isotonic），让"0.8"真的意味着约 80% 置信度；
- 每次改算法可回归测试误报/漏报率，替代凭感觉调参。

同时解决 §10 验收指标缺测量手段的问题，是整条改进路线的地基。

### 9.4 明确不做 / 暂缓

- **纯 LLM 比对**：结论不可复现、不可举证、离线部署重，与产品定位冲突。LLM 仅适合做可选的"证据解释器"（把 diff 翻译成评标语言），放在最后。
- **推翻现有评分体系**：五维加权的问题不是结构而是没校准，先有语料再谈换模型。

### 9.5 落地顺序

1. 合成语料生成器（地基，后续所有改进靠它验证）；
2. rsid + 共同错误 + 报价向量三个硬证据信号；
3. 段落对齐；
4. cross-encoder 复核带 + 用语料重新拟合权重。

## 10. 验收指标建议

- **准确性**：在校准语料集上，high 级围标判定误报率 <5%，同/洗稿分类与人工标注一致率 ≥90%；
- **性能**：5 份 × 100 页标书全管线（含语义）在普通办公机 <5 分钟；
- **可复现**：同输入同配置输出逐字节一致（normalize 已按确定性设计）；
- **可举证**：每个结论可下钻到原文页码/坐标。
