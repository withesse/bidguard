# 标书对比详细方案（原本·标书查重）

> 基线版本：v0.6.0 · 更新日期：2026-07-30（初版 2026-07-05，基线 v0.5.0）

> 第 9 节记录 v2 改进路线**的落地情况**（初版写于 v0.5.0，其内容已由 M0–M7 全部实现），

## 1. 目标与范围

**核心场景**：对同一招标项目下的 2–5 份投标文件做交叉比对（不是单文档自查重），找出雷同条款、深度洗稿、事实矛盾，并给出围标串标嫌疑分级。全程离线运行，结果可举证、可人工复核、可导出。

**输入**：docx / pdf（含扫描件）/ txt / md / xlsx，每份标书一个文档。

**输出**：相似度矩阵、条款聚类（8 类差异分类）、逐对高亮 diff、事实冲突清单、围标嫌疑等级（含信号分解）、六格式导出报告（HTML/JSON/CSV/Markdown/XLSX/DOCX）。

**明确不做**：大模型自动法律审查、云端协作。

## 2. 总体流程

```
导入期（每份文档独立，一次备料多次比对）
  ① 解析（含 PDF 隐藏层审计 / 渲染-OCR 交叉验证）
  → ② 标准化（NFKC + 不可见码点剥离 + 同形字折叠）
  → ③ 分块 → ④ 特征提取 → ⑤ 向量化（可选）

比对期（跨文档）
  ⓪ 招标文件对减（winnowing 指纹 → 标记「引用招标文件」，残差参与比对）
  → ⑥ 候选召回 → ⑦ 精排评分 → ⑧ 聚类（含多家共有查证）
  → 差异分类/diff → 事实冲突
  → 逐字雷同区间 + 对齐区段成型
  → 清单数值比对 → 矩阵/围标融合 → 校准与复核分带 → 报告
```

导入期结果落库（SQLite，迁移至 V23），embedding 按 `(normalized_hash, model_id)` 内容寻址缓存，
换比对参数不用重新解析。编排入口在 `src-tauri/src/services/compare_service.rs` 的 `run_compare()`。

三类正交证据分别由不同层产出：**文本**（召回→精排→聚类→逐字/区段）、**取证**（指纹类，见 §6）、
**数值**（清单类，见 §6）；其前后各有一层——前置的合法共享剥离（⓪）与入口对抗（①②）。

## 3. 导入期：解析与备料

### 3.1 文档解析（`src-tauri/src/engine/parse.rs`）

| 格式 | 方案 |
|------|------|
| DOCX | zip + quick-xml，识别表格、标题层级（含 WPS 中文样式 id） |
| PDF | 三级回落：pdfium → pdf-extract（纯 Rust）→ OCR（PaddleOCR ONNX） |
| TXT/MD | UTF-8 / GBK 自动识别 |
| XLSX | calamine，每行原子化为一个块，单元格以 ` \| ` 连接 |

关键处理：

- **页眉页脚剔除**：同一文本在 ≥60% 页面重复且出现 ≥3 页即判定；
- **OCR 版面保留**：返回每页 `{t,x,y,w,h}` 坐标 JSON，供原文预览叠加可选中文本层；
- **截断提示**：扫描件超 20 页会截断但显式提示（`truncation_notice`），不静默丢内容。

### 3.2 文本标准化（`src-tauri/src/engine/normalize.rs`）

规则链按序执行：

1. Unicode NFKC 全角转半角；
2. 中文数字 + 单位转阿拉伯形式（"五万元"→"50000元"，年份"二〇二六年"逐位转换）；
3. 连续空白压缩、换行归一化；
4. 标点/大小写规范（可配置）。

数字内小数点和千分位逗号保留，避免金额被破坏。这一步是让"洗稿改写"在词面层现形的基础。整条规则链按确定性设计，同输入跨版本输出一致。

### 3.3 分块（`src-tauri/src/engine/chunker.rs`）

三档粒度同表共存：

- **section**：≤6000 字（无标题时），带标题路径；
- **paragraph**：自然段落；
- **sentence**：jieba + 中英文标点边界。

两条领域特化规则：

- **表格行原子化**（`is_table_row`）：表格行不拆句，diff 走列对齐——表格的证据价值在金额/数量而非表头模板文字；
- **模板标记**（`is_template`）：与常见招标文件模板余弦 ≥0.7 的块打标，比对时可剔除但保留在库中可解释——避免"响应招标文件格式要求"这类必然雷同的内容制造误报。

### 3.4 特征提取（`src-tauri/src/engine/features.rs`）

每块同时生成：

- `exact_hash` / `normalized_hash`（SHA256）；
- jieba 分词 tokens；
- 字符 3-gram MinHash（128 个哈希，splitmix64 派生仿射变换，确定性、无外部依赖）；
- 实体：金额 / 日期 / 工期 / 比例 / 主体；
- TF-IDF 稀疏向量；
- 章节路径（`section_path`）、表格行/列表项标记。

### 3.5 语义向量化（可选，`src-tauri/src/engine/embed.rs`）

模型可选 bge-large-zh / multilingual-e5 系列，ONNX Runtime 本地推理，支持内置和按需下载。语义层专门用于抓"换句式洗稿"——词面全变但意思不变的段落。向量按 `(normalized_hash, model_id)` 缓存，重复比对不重算。

## 4. 比对期：召回与评分

### 4.1 五通道候选召回（`src-tauri/src/engine/candidate.rs`）

直接两两全比是 O(M²)，用五通道倒排召回压到 O(M·k)：

| 通道 | 条件 | 抓什么 |
|------|------|--------|
| exact_hash 桶 | 哈希相同 | 原样照抄 |
| normalized_hash 桶 | 标准化后相同 | 改格式不改字 |
| 3-gram MinHash 倒排 | 共享 ≥3 个 gram；df ≥ max(256, N/10) 的高频 gram 停用 | 局部改写 |
| TF-IDF TopK | 点积 ≥0.25，每块 top 100 | 主题相似 |
| Embedding TopK | 余弦 ≥0.78，每块仅取 5 个（宁缺毋滥） | 深度洗稿 |

只召回跨文档候选，同文档内块不互比。

### 4.2 精排评分（`src-tauri/src/engine/scoring.rs`）

五维加权（启用语义时为六维）：

| 维度 | 权重（无语义） | 说明 |
|------|------|------|
| 词面相似 | 0.40 | token 余弦/Jaccard |
| 字符 n-gram | 0.30 | Jaccard |
| 实体相似 | 0.15 | 金额/日期等集合重合度；**表格行实体权重 ×2** |
| 结构相似 | 0.10 | 章节路径 Dice，剥掉文档标题根（标书 H1 必然不同） |
| 顺序相似 | 0.05 | 相对位置差 |

启用语义后 embedding 占 0.35，其余按比例压缩。

两个防误报设计：

- **不可测维度踢出分母重分配**（而非记 0 或 1）：双空记 1.0 会给无关短文本凭空加满分权重；
- **短文本动态阈值**：<30 字阈值上浮 +0.08 封顶 0.98——"按合同执行。"这类短句词面重合天然高。

### 4.3 聚类（`src-tauri/src/engine/clustering.rs`）

边分 ≥0.7 进并查集生成连通分量；成员 ≥4 且边密度 <0.55 的分量做**低内聚迭代拆分**（删最弱边递归），解决 A≈B≈C 但 A≉C 的"过桥"误聚。每文档在簇内选一个 primary（与其他文档平均相似度最高者），其余为 duplicate_candidate。

### 4.4 八类差异分类 + 分级 diff（`src-tauri/src/engine/diff.rs`）

| 分类 | 判定 |
|------|------|
| same | 分数 ≥0.95 |
| minor_change | 0.85–0.95，无关键实体变化 |
| rewrite（洗稿） | 0.70–0.85 且语义 ≥0.80、词面 <0.50 |
| changed | 0.70–0.85 |
| uncertain | 0.55–0.70，不硬判，转人工复核 |
| added / deleted | 单边存在（deleted 低于 0.55 下限时降为 uncertain） |
| conflict | 事实冲突改判，优先级最高 |

diff 按长度分级：≤60 字字符级，≤400 字词级，长段落句级再细化，表格行按列对齐逐格比。

## 5. 事实冲突检测（`src-tauri/src/engine/fact.rs`）

抽取金额（含大写、千分位、¥ 前缀）、日期、工期、比例、主体，主体做**阵营归一**（招标人/甲方→owner，投标人/乙方→supplier）。三条防误报规则：

- **集合互不包含才算冲突**：A 列了三笔付款、B 只提首笔，是信息缺失不是矛盾；
- **跨阵营互换才触发**（甲方付款变成乙方付款）；同阵营表述差异（"我司" vs "我公司"）不触发；
- **日期粒度兼容**："2026 年 6 月"与"2026 年 6 月 10 日"不判冲突。

## 6. 三类证据与围标融合（`src-tauri/src/engine/collusion.rs`）

围标判定不再是「文本相似度 + 少量旁证」，而是**三类正交证据**汇入统一融合层。共 16 类信号，
全部以连续特征 x∈[0,1] 参与（不是命中即满分）：

| 类别 | 信号 | 依据 |
|------|------|------|
| 文本 | 相似峰值、多文档雷同簇、多家异常一致、共有罕见词、事实冲突 | §4 §5 |
| 取证 | rsid 交集、PDF 血缘、图片同源、共同错误 | `fingerprint.rs`（改抬头换措辞洗不掉） |
| 数值 | 逐项雷同率、共享算术错误、规律性差异、单价相关性、机制反事实 | `boq.rs`（`mechanism` 仅描述性，不计权） |
| 对抗 | 规避特征 | `pdf_audit.rs` / `pdf_xcheck.rs` / `confusables.rs` |

**融合方式**：`z = b + Σ wᵢ·xᵢ`，权重由合成语料拟合（`fixtures/calibration/collusion_lr.json`，
IRLS + L2 向经验先验收缩 + 非负投影；系数符号异常或文件损坏则回退经验权重并告警）。
`weight` 字段语义随之从「权重占比」变为**该信号的对数似然比贡献**，信号分解按贡献降序仍可解释。

**LR 之外保留的显式规则**（产品纪律，不是统计项）：取证类合计封顶 `FORENSIC_CAP=0.45`、
数值类封顶 `NUMERIC_CAP=0.45`（防与文本双重计数）、以及**条件化硬命中 floor**——仅当已导入招标文件
且豁免对减生效时，rsid/PDF 硬命中才把等级下限抬到 medium（永不自动 high）。

**对外呈现**：以 **ENFSI 式证据强度口头等级**（强 / 中等 / 弱 支持「同源编制」假设）替代概率数值；
概率仅留在 JSON 技术字段并注明「合成语料校准、非串通概率」——避免检察官谬误。条款另按
`低优先级抽查 / 需人工复核 / 重点标红` 三带排队（`engine/calibrate.rs`，Platt + split conformal）。

相似度矩阵有三套口径（`matrix.rs`）：`matrix`（对减后·聚类，**风险分级唯一输入**）、
`matrixOriginal`（未对减，对照用）、`segmentMatrix`（对齐区段按 chunk 去重）。

## 7. 结果呈现与人工复核

- **矩阵页**（`Matrix.tsx`）：热力矩阵（三口径可切换）+ 取证指纹面板 + 围标结论与信号分解；
- **条款详情**（`ClusterDetail.tsx`）：多文档并排（十天干匿名列头）、diff 高亮、事实冲突表、批注；
- **区段视图**（`PairSegments.tsx`）：文档对粒度的连续对齐区段，双栏三级高亮（深红逐字铁证 / 橙锚点雷同 / 黄 gap 差异），只读；
- **商务标数值**（`BusinessNumeric.tsx`）：雷同率热力表、单价散点图（点落对角线＝完全雷同）、共享算术错误明细；
- **人工复核三态**：待定 / 确认 / 排除——**只挂在聚类上**，区段视图不引入第二套状态；机器给证据与分级，结论权属评标委员会；
- **导出**（`export/`）：六格式**证据章节齐平**，含常驻的「检查方法与局限」一节（列已执行检查项与各自可清除性，堵「没有取证章节＝干净」的沉默背书）。

## 8. 已知短板（v0.6.0 现状）

1. **校准语料是合成的**（最高优先）：权重与阈值已由语料拟合而非拍脑袋，但语料由程序变换生成、
   非真实判例，故标注为「实验性校准」。**这也是三带当前不做分流的原因**——合成语料无法区分
   「同源编制」与「合法共享」（独立撰写的文档集里同样存在完全一致的范本段落），故全部路由到
   「需人工复核」并如实说明。补真实脱敏语料后重跑 `fit-calib` 即自动启用。
2. **数值层不覆盖扫描件**：OCR 路径不产表格行，清单比对仅支持 xlsx / docx / 文本 PDF。
3. **工程债**：Embedder 单槽导致语义推理串行；`options_hash` 版本靠手工维护；前端组件测试覆盖仍低。
4. **许可密钥**：当前发布版内嵌开发验签公钥，正式发布前须按 `license-activation-scheme-v2.md`
   的 A 组清单换发（硬性阻断项）。

## 9. v2 改进路线的落地情况

> 本节初版写于 v0.5.0，是当时提出的改进方向；**其内容已由 M0–M7 全部实现并随 v0.6.0 发布**。
> 逐条设计、验收标准与全局裁决见 **[bid-comparison-execution-plan.md](bid-comparison-execution-plan.md)**。

| 原计划 | 落地 |
|--------|------|
| 9.1 取证层：rsid / 共同错误 / 报价向量 / 图片哈希 | ✅ M1 + M6，另补 PDF 血缘（XMP GUID / trailer ID / 字体子集） |
| 9.2 段落对齐替代散点配对 | ✅ M5：seed-chain-align + 逐字雷同区间（后缀自动机）+ 区段视图 |
| 9.2 cross-encoder 复核带 | ✅ M7，但**降级为「复核建议」**：簇保持 uncertain，只排序不改判（黑盒模型不宜下指控性分类） |
| 9.3 合成语料 + 回归门禁 | ✅ M3：1750 段对 + 12 组文档集，CI 每次提交比对指标，漂移即失败 |
| 9.3 权重逻辑回归拟合 + 概率校准 | ✅ M7：对**全量 16 类特征**拟合（非原计划的五信号）+ Platt + 共形三带 |
| — （原计划未覆盖） | ➕ 招标文件对减、入口对抗层、分区阈值、多家共有查证 |

**当时的判断事后看基本成立**，两处修正值得记录：

- 原计划让 cross-encoder **自动改判**洗稿，实际降级为排序建议——「相关 ≠ 同源改写」，
  黑盒模型不该产出指控性分类；
- 原计划只拟合五信号，但落地时信号已增至 16 类，若只拟合旧五类，新证据会成为死列。

### 9.4 明确不做 / 暂缓（维持原判断）

- **纯 LLM 比对**：结论不可复现、不可举证、离线部署重，与产品定位冲突；
- **跨工作区背景库**：破坏「同输入同输出」可复现性，且跨项目计数外溢有保密观感——**已砍**，
  改为随包版本化的静态范本库；
- **机制感知反事实基准价**：已实现但**仅作描述性输出**，`flip_prob` 不进围标信号——公式族覆盖窄、
  评标办法靠人工录入，未经真实语料验证前不入分级。

## 10. 验收指标与实测

| 指标 | 目标 | 现状 |
|------|------|------|
| 可复现 | 同输入同配置逐字节一致 | ✅ 已达成（含修掉哈希表迭代序导致的浮点非确定性） |
| 可举证 | 每个结论可下钻到原文页码/坐标 | ✅ 逐字区间、区段锚点、清单条目均带 chunk/页码锚点 |
| 回归护栏 | 算法改动有机械门禁 | ✅ `corpus_regression` 进 CI（召回率 / per-label F1 / 围标 AUC） |
| 判定准确性 | high 级误报率 <5%、分类一致率 ≥90% | 🟡 合成语料上指标良好（留出集 AUC 1.0、ECE 0.005），但**不能外推到真实标书**——需真实脱敏语料回测 |
| 性能 | 5 份 × 100 页全管线 <5 分钟 | 🟡 合成语料与 fixture 上远快于此，未在真实大标书上系统测量 |

> 最后一行是这套方案当前最诚实的短板：**所有量化指标都测自合成语料**。它足以防回归，
> 不足以证明真实检出率——把这一点写在验收表里，比给出一个漂亮但无依据的数字更有价值。
